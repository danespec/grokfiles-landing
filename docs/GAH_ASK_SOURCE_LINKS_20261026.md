# Ask GAH: ID-only results regain source links

The live October 26 query “Which documents mention Leon Black?” returned eight result rows containing EFTA IDs but no read_url, url or source_url. The Ask GAH renderer only linked explicit URLs, leaving those results as plain text. The new renderer uses a complete EFTA identifier as a fallback archive locator and includes that identifier in the visible label. Existing valid source URLs retain precedence, including direct PDF URLs. Numeric mailbox IDs do not become invented EFTA links. Unsupported URL schemes remain rejected, and labels remain textContent rather than injected markup.

Both current shared-shell variants are covered: the main newsroom script and Barak’s specialized script. Their replacement files have new versioned URLs so cached old JavaScript is not reused. Worker shell enhancement upgrades the old references and explicitly permits the two new script paths in the existing CSP; no wildcard script permission is added. Old asset URLs remain available for compatibility. The scripts otherwise preserve their respective existing behavior, including newsletter and Barak functions.

Validation: the actual rendering function from each new file is exercised with ID-only results, lower-case/whitespace IDs, all four supported ID fields, valid explicit URLs, unsafe URLs, a separate numeric leak ID, incomplete/oversized/path-like IDs, malformed rows, missing labels and text containing HTML. Actual Worker tests verify current script delivery on the homepage, search, Ask GAH watch page and Barak entity page, plus JavaScript asset content types and CSP. Existing browser-script, 32-page media, 20 staging and generator-idempotency checks pass. Eight recorded live-query archive destinations returned HTTP 200; this validates those routes, not the generated answer’s factual accuracy.

Preview browser QA uses the real Worker-rendered search page and the patched script with a deterministic response containing the eight recorded result IDs. It tests link rendering rather than current retrieval quality. A production answer, live post-deployment behavior and full source accuracy are not certified by the fixture. The actual protected preview remains under owner-only Cloudflare Access. Production deployment requires Thomas’s approval.

This patch does not change archive indexability, sitemap membership, retrieval ranking, answer text, corpus coverage or the media transcript gaps. The earlier watch-page copy describing the missing-link observation remains an accurate dated historical check; the production fix should be recorded after deployment.

# GAH Measurement Protocol — November 17, 2026
The existing `/api/analytics/event` endpoint was a dry-run public relay; it is now status-only. No caller-provided event names, routes, IDs or arbitrary parameters are forwarded. Only successful consented same-origin archive searches on the apex are measured, using the existing first-party GA client ID and the authoritative result count. The two events are mutually exclusive. Explicit effective browser consent, a current shared consent preference, existing GA cookie, privacy headers and an atomic limiter are required. Denied/pending/withdrawn consent, automation, staging, missing limiter or missing credentials suppress delivery. Advertising consent is denied; no search text, result content, IP, account identity, purchase or pageview is sent. No session or engagement-time inference is made.

Set encrypted `GA4_API_SECRET` and `GA4_MEASUREMENT_ID`, then `GA4_MP_ENABLED=true` only after the status-only endpoint is deployed. `GA4_MP_DRY_RUN=true` or removal of the enable flag disables sends. No historical replay. Test Google payload validation with /debug/mp/collect, which does not populate reports and does not verify credentials. Confirm observed events in GA4 separately. Never print or commit secrets. Do not use synthetic searches to populate production reports.

Tests: node tests/test_ga4_measurement_protocol.mjs, tests/test_analytics_html.mjs, tests/test_analytics_single_pass.mjs, tests/test_analytics_browser.mjs (isolated, no live events). Current scope is apex archive search only; wiki and Ask GAH retain their existing analytics.
